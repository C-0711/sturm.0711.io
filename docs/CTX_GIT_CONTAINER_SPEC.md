# CTX_GIT_CONTAINER_SPEC.md — Knowledge Container Git Policy

**Status:** ENFORCED  
**Signed off by:** Mastermind C, 2026-05-24  
**Enforced by:** B9 gitchain-service (creation), G5 CI gate (publish)

---

## Rule

**Every Knowledge Container MUST have its own git repository.**

No exceptions. A container without a git repo is not a compliant container — it cannot be published, linked, or trusted.

---

## Required Repository Layout

```
<container-root>/
├── manifest.json        # Container metadata and provenance
├── events.jsonl         # Append-only event log (one JSON object per line)
├── signature            # Cryptographic signature from C2 (Mastermind C's signing authority)
└── atoms/               # Content atoms directory (individual knowledge units)
    └── <atom-id>.json   # One file per atom
```

### manifest.json — Required Fields

```json
{
  "id": "<container-id>",
  "version": "<semver>",
  "created_at": "<ISO8601>",
  "owner": "0711-intelligence",
  "tenant": "<tenant-id>",
  "imported_pre_git": false,
  "retroactive_git_init": null
}
```

For retroactively git-initialized containers:
```json
{
  "imported_pre_git": true,
  "retroactive_git_init": "YYYY-MM-DD"
}
```

### events.jsonl — Event Format

Each line is a JSON object:
```json
{"ts": "<ISO8601>", "type": "<event-type>", "actor": "<agent-id>", "payload": {}}
```

### signature — C2 Signature

- Generated by C2 (Mastermind C's signing authority)
- Signs the SHA-256 of `manifest.json` + `events.jsonl` concatenated
- Must be present at publish time; may be absent during active development

## Required Commit Protocol

**Every mutation to a container MUST produce a git commit.**

### Commit Message Format

```
<type>(ctx): <description>
```

Where `<type>` is one of:
- `feat` — new content or atoms added
- `fix` — correction to existing content
- `chore` — metadata updates, provenance markers, housekeeping

### Examples

```
feat(ctx): add atom 0711-bosch-safety-protocol-v2
fix(ctx): correct tenant ID in manifest
chore(ctx): mark as retroactive git init (2026-05-24)
chore(ctx): update signature after manifest amendment
```

### Rules

1. No uncommitted changes at publish time — enforced by G5 CI gate
2. Commit must include all modified files (`git add -A`)
3. Empty commits are not permitted
4. Force-pushes are prohibited on published containers (only allowed on draft branches)

---

## Enforcement

### B9 gitchain-service — Creation Gate

- Runs at container creation time
- Refuses to register any container that lacks a git repository
- Initializes the git repo if creating a new container from scratch
- Does NOT retroactively fix old containers — that requires manual P4-class work

### G5 CI Gate — Publish Gate

- Runs at publish time (before container is linked or made queryable)
- Checks:
  - [ ] Git repo exists and is initialized
  - [ ] Working tree is clean (no uncommitted changes)
  - [ ] `manifest.json` exists and is valid JSON
  - [ ] `events.jsonl` exists (may be empty on first publish)
  - [ ] `signature` exists
  - [ ] Commit history is non-empty
- Fails the publish if any check fails

## Retroactive Compliance (Imported Containers)

Containers that existed before this policy was enacted (pre-git) must be marked explicitly:

1. Run `git init` in the container root
2. Add `"imported_pre_git": true` and `"retroactive_git_init": "<date>"` to `manifest.json`
3. Commit: `chore(ctx): mark as retroactive git init (<date>)`
4. The container is now "legacy-compliant" — it passes G5 gate but carries the provenance marker

See `MIGRATION_RUNBOOK.md` for the full migration procedure.

## Rationale

Git-per-container gives us:
- **Immutable audit trail** — every change is a commit, attributable and timestamped
- **Rollback capability** — bad mutations can be reverted cleanly
- **Diff-ability** — compare any two versions of a container precisely
- **CI/CD integration** — G5 gate enforces quality at publish time
- **Trust chain** — signature + git history = cryptographically verifiable provenance

## Required Repository Layout

Every CTX container git repository MUST contain:

```
container-id/
  .git/                    # git repository (MANDATORY)
  manifest.json            # container metadata: id, visibility, createdAt, type
  events.jsonl             # append-only audit log (B7 schema)
  signature                # Ed25519 signature of manifest (C2)
  atoms/                   # content atoms (optional, for semantic containers)
    *.md                   # individual atom files
  provenance.json          # for retroactively-inited containers only
```

### manifest.json schema
```json
{
  "id": "0711:ctx:<namespace>:<uuid>",
  "visibility": "public|private",
  "createdAt": "<ISO8601>",
  "type": "knowledge|workflow|product",
  "namespace": "<string>",
  "version": "v1"
}
```

## Required Commit Protocol

Every mutation to a container MUST produce a git commit:

### Commit message format
```
<type>(ctx): <description>
```

Types:
- feat(ctx): new content or capability added
- fix(ctx): correction to existing content
- chore(ctx): metadata updates, provenance markers
- seal(ctx): Ed25519 signature applied (C2)
- anchor(ctx): on-chain anchor recorded (C5)

### Rules
1. No bare file writes without a commit
2. Commit must include the author: git -c user.name="<agent-id>" -c user.email="<agent-id>@0711.io" commit
3. Every commit is audited via events.jsonl (events_appended event type)
4. Sealed containers: only chore/anchor commits allowed after sealing
